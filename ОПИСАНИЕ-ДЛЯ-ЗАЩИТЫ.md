# Дипломная работа: «Доска объявлений» (Ads Application)

## 1. Актуальность и цель

Цель работы — разработать REST API для **доски объявлений** — сервиса, где пользователи могут регистрироваться, размещать объявления о товарах/услугах и комментировать чужие объявления. Аналог — Авито / Юла, упрощённый до уровня учебного проекта.

Задачи:
- реализовать регистрацию и аутентификацию
- CRUD для объявлений и комментариев
- загрузку и хранение изображений
- разграничение прав доступа (USER / ADMIN)
- документировать API и покрыть код тестами

## 3. Архитектура

Классическая **трёхслойная архитектура** REST-приложения:

```
Controller (REST) → Service (бизнес-логика) → Repository (JPA) → PostgreSQL
```

Пакеты:
- `controller` — REST-эндпоинты, принимают и возвращают DTO
- `service` — бизнес-логика: `UserService`, `AdService`, `CommentService`, `AuthService`, `ImageService`
- `repository` — Spring Data JPA
- `model` — сущности (`User`, `Ad`, `Comment`, `Role`)
- `dto` — объекты запросов/ответов (`record`)
- `mapper` — MapStruct-мапперы
- `config` — безопасность и OpenAPI
- `exception` — глобальный обработчик ошибок
- `filter` — CORS-фильтр
- `util` — `SecurityUtils` (проверка прав)

Данные между слоями передаются через **DTO** — это изолирует клиентов от внутренней структуры сущностей (не отдаём пароль, поля `id` и т.д.).

## 4. Доменная модель

Три сущности:

- **User** — `id` (автоинкремент), `email` (уникальный, логин), `password` (BCrypt-хэш), `firstName`, `lastName`, `phone` (+7 XXX XXX-XX-XX), `role` (USER/ADMIN), `image` (путь к аватару)
- **Ad** — `id`, `title`, `description`, `price` (0..10 млн), `image`, `author` (FK → User)
- **Comment** — `id`, `text`, `createdAt` (автоматически через `@PrePersist`), `author` (FK → User), `ad` (FK → Ad)

Связи: `User 1→* Ad`, `User 1→* Comment`, `Ad 1→* Comment`.

> **Почему `GenerationType.IDENTITY`?** Это автоинкремент на стороне БД (PostgreSQL `IDENTITY`). При сохранении Hibernate сразу выполняет `INSERT` и получает сгенерированный ключ — просто и быстро, без дополнительных sequence-объектов. Подходит для PostgreSQL/MySQL.

## 5. Функциональные возможности и API

### Авторизация
- `POST /register` — регистрация: проверка на дубликат email, хэширование пароля BCrypt, возврат ID нового пользователя
- `POST /login` — вход: поиск по email + проверка пароля через `PasswordEncoder.matches()`

### Пользователи
- `GET /users/me` — информация о себе
- `PATCH /users/me` — обновление профиля (MapStruct `updateFromDto` игнорирует null)
- `POST /users/set_password` — смена пароля (проверка текущего пароля)
- `PATCH /users/me/image` — загрузка аватара

### Объявления
- `GET /ads` — все объявления
- `GET /ads/me` — объявления текущего пользователя
- `GET /ads/{id}` — детали объявления (с данными автора)
- `POST /ads` — создание (`multipart/form-data`: JSON + опциональная картинка)
- `PATCH /ads/{id}` — обновление
- `DELETE /ads/{id}` — удаление
- `PATCH /ads/{id}/image` — обновление картинки

### Комментарии
- `GET/POST /ads/{id}/comments` — список / добавление
- `PATCH/DELETE /ads/{adId}/comments/{commentId}` — изменение / удаление

## 6. Безопасность

**Аутентификация** — HTTP Basic. Пароли хранятся только как BCrypt-хэш (`BCryptPasswordEncoder`), в БД не сохраняется открытый пароль.

**Авторизация** — два уровня:
1. **Уровень URL** (`WebSecurityConfig`): публичный доступ к Swagger и `GET /ads/**`; для `POST/PATCH/DELETE` и работы с `/users/**` — роли USER/ADMIN. CSRF отключён (REST API, Basic Auth), CORS настроен.
2. **Уровень данных** (`SecurityUtils.checkModifyPermission`): даже авторизованный пользователь не может редактировать/удалять **чужое** объявление или комментарий. Проверка: владелец ресурса = текущий пользователь ИЛИ роль ADMIN. Иначе — 403.

`UserDetailsServiceImpl` загружает пользователя из БД по email и передаёт роль в Spring Security.

## 7. Работа с изображениями

`ImageService` сохраняет файлы в файловую систему (`images/` и `avatars/`, пути из `application.properties`):
- валидация content-type: только **JPEG / PNG / GIF**
- имя файла — `{id}.{расширение}` (например, `avatars/1.png`)
- при обновлении старое изображение удаляется, новое перезаписывается
- путь к файлу сохраняется в сущности (`Ad.image`, `User.image`)

## 8. Производительность БД

- `AdRepository.findAll()` — `@EntityGraph(attributePaths = {"author"})` — подтягивает автора одним JOIN
- `CommentRepository.findAllByAd_Id()` — JPQL `JOIN FETCH c.author`

Обе оптимизации решают **проблему N+1** (чтобы не было N запросов на автора для N записей).

## 9. Обработка ошибок

Глобальный `@RestControllerAdvice` (`ControllerAdvice`) перехватывает исключения и возвращает единый формат `AnswerErrorDto` (код, сообщение, timestamp):
- `EntityNotFoundException` → 404
- `AccessDeniedException` → 403
- `InvalidOldPasswordException` / `BadCredentialsException` → 400 / 401
- `UserAlreadyExistsException` → 409
- ошибки валидации `MethodArgumentNotValidException` → 400
- неверный тип параметра, битый JSON, метод не найден → 400/405

Это изолирует клиента от системных stacktrace и унифицирует ответы.

- Команда: `./mvnw test`
